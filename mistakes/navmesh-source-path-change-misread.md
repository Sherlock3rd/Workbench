# NavMesh 源文件路径更改误读为点位编辑

## 基本信息
- 日期：2026-06-09
- 分类：需求理解 / 工具交互
- 任务：为 `levelpoints-navmesh-viewer` 增加原文件索引显示、源文件目录路径更改、刷新重新加载功能

## 问题现象
- 用户要求的是源文件索引显示、源文件路径/目录更改，以及刷新重新加载原文件。
- 实现时误把“更改功能”理解成了点位内容编辑，加入了坐标、`ObjID`、`ObjType`、`AreaID` 编辑和下载改后 JSON 的入口。
- 中断修复过程中还导致 `levelpoints-navmesh-viewer` 的 `SKILL.md`、agent 配置和脚本目录文件短暂缺失，随后已恢复。

## 原因分析
- 没有在有歧义的“更改功能”上二次确认，违反“遇到不确定事项必须先二次确认”的规则。
- 将工具交互层面的“更换源文件路径”误扩展成数据内容编辑，超出了用户当前需求。

## 修复动作
- 移除点位内容编辑和下载改后 JSON 的入口。
- 保留并实现正确能力：显示 `LevelPoints.json` 的 `components[]` 原文件索引；可按索引定位和复制；显示当前 NavMesh / LevelPoints 源路径；通过浏览器文件选择器更改 NavMesh 或 LevelPoints 文件；刷新按钮重新读取最近授权选择的源文件。
- 恢复 `.cursor/skills/levelpoints-navmesh-viewer/` 下的 `SKILL.md`、`agents/openai.yaml` 和三个脚本文件。

## 预防办法
- 用户说“更改路径 / 更改目录 / 更改原文件”时，默认理解为切换读取来源，不得自行加入源数据内容编辑。
- 只有用户明确说“编辑点位数据 / 修改坐标 / 导出改后 JSON / 写回源文件”时，才设计点位内容编辑功能。
- 对浏览器静态 HTML 的本地文件刷新能力，必须说明需要文件选择器授权，不能承诺静默读取任意磁盘路径。
