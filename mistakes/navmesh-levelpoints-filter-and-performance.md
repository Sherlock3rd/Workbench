# LevelPoints 点位筛选与 NavMesh 底图性能

## 基本信息
- 日期：2026-06-09
- 分类：性能 / 信息保真
- 任务：启动并迭代 `levelpoints-navmesh-viewer` HTML 预览

## 问题现象
- 大地图 NavMesh 全量绘制时页面容易卡顿。
- 初期曾通过抽样或过度简化降低卡顿，但会丢失区块、分区和轮廓信息。
- 恢复脚本时曾把 `极简模式` 退化成按线段长度过滤，导致“按围合面积隐藏内部小区域”的合并隐藏逻辑丢失。

## 修复动作
- 保留三种底图模式：`完整 NavMesh`、`分区边界简化`、`极简模式`。
- `完整 NavMesh` 保留可见 polygon 和分区颜色。
- `分区边界简化` 绘制外轮廓和分区边界，保留颜色分区信息。
- `极简模式` 必须保留大外轮廓连通块，并按边界侧连通块的包围面积过滤内部小围合区域；当前阈值为 `< 200`。由于原始边匹配会把大量内部碎边识别成 `outer`，小 `outer` 碎边也要按面积过滤。
- 更换 NavMesh 源文件后，前端也必须重新计算边界连通轮廓面积，不能只依赖初始 Python 预计算结果。

## 预防办法
- 大地图优化不能通过抽样丢弃 NavMesh 分区信息。
- 极简模式不能用线段长度过滤替代围合面积过滤。
- 极简模式不能按 `ProvinceID` / `GroupIndex` 大分区聚合面积过滤，应按边界线段连通组件的包围盒面积过滤。
- 不得把所有 `kind=outer` 的边无条件保留；应保留大外轮廓连通块，小 `outer` 碎边同样按 `< 200` 面积阈值隐藏。
